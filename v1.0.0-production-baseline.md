# SolveHub — Master `v1.0.0-production` Baseline Specification

**Document Identifier:** `SOLVEHUB-BASELINE-v1.0.0`

**Release Tag:** `v1.0.0-production`

**Status:** RECONCILED & LOCKED BASELINE

**Product Concept:** Hybrid calculation workspace merging Calculator.net (structured utility), Soulver (natural language text + math), and Notion (block-based document UI).

## 1. Core System Architecture & Technology Stack

- **Frontend Framework:** Next.js (React) with TypeScript
- **Styling & Design System:** Tailwind CSS
- **Client-Side Storage Engine:** Dual-layer architecture utilizing Web Storage (`localStorage`) partitioned under key namespaces (`solvehub_workspace_v1`, `solvehub_history_v1`) with an automatic, zero-latency runtime in-memory fallback driver for private sessions and SSR hydration cycles.
- **Source Control & Versioning:** GitHub (Feature branching, PR controls, tagged releases)
- **Hosting & Infrastructure:** Firebase App Hosting (Server-Side Rendering via Cloud Run, static asset distribution via Cloud CDN, automated GitHub integration)

## 2. Locked Layout & Viewport Framework

The application shell is constrained to a fixed 100vh viewport structure divided into a 3-section horizontal panel grid.

| **Panel / Section** | **Desktop Dimension Rules** | **Operational Role & Capabilities** | **Mobile Adaptation (<768px)** |
| --- | --- | --- | --- |
| **Section A: Left Navigator** | Fixed `w-[260px]` (`min-w-[260px] max-w-[260px] flex-shrink-0`) | Workspace switcher, global multi-calculator search, Canvas vs. Curated mode toggles, session history stack, global settings. | Collapses into an off-canvas overlay menu accessed via hamburger button. |
| **Section B: Center Workspace** | Fluid `flex-1 min-w-0 overflow-y-auto` | **Canvas Mode:** Borderless block text editor for natural language calculations.

**Curated Mode:** Categorical search filters with structured input fields and dynamic dual sliders. | Expands to occupy 100% of available viewport width (`w-full`). |
| **Section C: Right Results Column** | Fixed `w-[320px]` (`min-w-[320px] max-w-[320px] flex-shrink-0`) | **Canvas Mode:** Live line-by-line numerical results with dynamic variable tags.

**Curated Mode:** Card calculation receipts and visual formula logic graphs. | Converts into an interactive floating bottom sheet drawer (`h-[60vh]`) with pull-tab control. |

## 3. Product Operating Modes

### Mode 1 — Canvas Mode (Natural Language Playground)

- **Center Workspace (Section B):** Distraction-free text editor supporting Notion-style block structures. Users enter mixed text and mathematical equations (e.g., `"Base Rent = $2,400 per month"`).
- **Right Results Column (Section C):** Renders live, line-aligned numerical evaluations in real time, accompanied by interactive variable tags and unit metadata.

### Mode 2 — Curated Mode (Structured Tool Library)

- **Center Workspace (Section B):** Categorical discovery hub (Finance, Health, Science, Unit Conversion). Selecting a tool renders structured input fields and dynamic adjustment sliders.
- **Right Results Column (Section C):** Renders card-based calculation receipts, total breakdowns, copyable logic summaries, and formula visualizer graphs.

## 6. Context Protection & Architectural Drift Rules

1. **Immutable Panel Widths:** Section A (`260px`) and Section C (`320px`) are fixed pixel layout boundaries. Section B must absorb all remaining horizontal space via fluid flex parameters (`flex-1 min-w-0`).
2. **Schema Key Integrity:** Variable names generated during math modeling (e.g., `annual_interest_rate`) are immutable and must match across TypeScript interfaces, Tailwind form controls, Web Storage keys, and visual receipt cards.
3. **Cross-Mode Variable Hydration:** Switching between Canvas Mode and Curated Mode automatically parses and populates variable values across interfaces without state loss.

## 7. Parallel Execution & Continuous Deployment Model

Development proceeds in two synchronized workstreams that converge at a pre-flight integration gate prior to production deployment:

- **Stream 1 (Product & Design):** Gemini drafts PRD $\rightarrow$ Google AI Studio verifies math AST parser $\rightarrow$ Stitch builds Tailwind UI specs $\rightarrow$ Local component assembly $\rightarrow$ Omni performs visual QA audit.
- **Stream 2 (DevOps & Infrastructure):** Initialize GitHub repository $\rightarrow$ Antigravity generates `.github/workflows/deploy-preview.yml` and `apphosting.yaml` $\rightarrow$ Firebase App Hosting project initialization.
- **Convergence Gate & Release:** Commits pushed to GitHub feature branches trigger Antigravity automated preview deployments to Firebase App Hosting. Upon Project Owner sign-off on the live preview URL, the PR merges into `main` for production release.
